# V1-M2c 目标设备样本与时间基采集规程

状态：Ready for capture v0.1

更新时间：2026-07-22

目标设备：CS-C6c-V101-1J4WF 摄像头（带麦克风）、CS-EP-SDNL1 睡眠仪

## 1. 本阶段要证明什么

V1-M2c 不要求立即完成萤石全量 SDK 开发。它先取得可追溯的目标设备样本，证明：

1. C6c 实际输出的视频、音频、容器、编码、分辨率、帧率和时间戳形态。
2. 视频与音频是否来自同一容器/同一时钟；若分离，偏移如何测量。
3. 已冻结模型在真实机位、夜视、距离、遮挡和困难横卧上的覆盖与质量。
4. CS-EP-SDNL1 实际能导出或通过 API/SDK 返回哪些字段、单位、时间粒度和缺失表达。

公开 URFD/FLEURS 结果不能替代上述任一项。

## 2. 安全与同意

- 只采集明确知情同意的成年人；真实身份与媒体目录分开保存。
- 不要求老人完成危险跌倒。模拟跌倒只由健康成年人在安全垫、保护人员和无障碍区域中完成；条件不足就跳过。
- 摄像头语音必须主动开启和告知，不做全天监听。
- 睡眠数据属于敏感健康信息；本阶段报告只保留字段结构、时间和质量摘要。
- 实际 capture manifest、原始媒体、设备序列号、验证码、token 和 consent 文件都放在 Git 忽略的受控目录。

## 4. 音视频时间基实验

每个包含语音的 clip：

1. 录制开始后做一次画面可见且声音清晰的拍手/击板，结束前重复一次。
2. 同时记录设备端显示时间、接收端 UTC 时间和本地文件落盘时间。
3. 保留原始容器，不先抽轨或重编码。
4. 检查是否存在 video/audio track、各自 time_base、首尾 PTS、duration、帧/包间断和音频采样率。
5. 若视频与音频分开导出，用两次同步事件估计起始 offset 和随时间漂移；不能只手工平移到“看起来同步”。

当前 `probe-media` 可先记录文件摘要、视频参数和 WAV 参数；容器音轨与逐包 PTS 仍需 ffprobe/PyAV 探针补齐后才能关闭时间基验收。

## 5. Capture manifest

模板见 `configs/v1-m2c-capture-manifest.example.json`。实际文件建议保存为：

```text
data/raw/v1-m2c/<capture_id>/capture-manifest.json
data/raw/v1-m2c/<capture_id>/camera/*.mp4
data/raw/v1-m2c/<capture_id>/sleep/*
data/raw/v1-m2c/<capture_id>/consent/<local-reference>
```

每个 clip 至少记录：

- `scenario_id`、动作、是否有真值时间窗。
- `device_ref`、固件/能力快照引用、采集方式（直播录制、回放导出、SDK 导出）。
- UTC 起止时间与媒体相对时间。
- 机位高度、俯仰角、人与镜头距离、光照/夜视、遮挡。
- 原始文件 SHA-256、字节数、容器与轨道事实。
- 同意引用、执行人、保护人员和安全垫状态。
- 失败、重试、断流、无音频和权限问题，不删除失败证据。

模板中的占位符没有证据等级；只有实际文件、实际能力快照和可复查调用才能形成 E2/E3。

## 6. 睡眠仪最小样本

优先级从高到低：

1. 脱敏 API 响应与接口文档版本。
2. SDK 导出的原始 JSON/CSV。
3. App 人工导出文件。
4. 仅截图只能说明 UI 出现字段，不足以冻结机器接口。

每份样本记录请求/导出时间、设备时区、报告覆盖区间、记录数、原字段、单位、采样/聚合周期、null/离床/离线表达和报告生成延迟。心率、呼吸率、在离床、睡眠时长、觉醒、分期、HRV、AHI、血氧逐项写“出现/未出现/语义待确认”，不得根据商品硬件能力补字段。

首份文件到达后先运行：

```bash
kangshield-info profile-sleep <export.json-or-csv> \
  --evidence-level E2 \
  --source-type sdk_export
```

自动字段映射仍只是 candidate，单位和医学语义需人工确认。

## 7. 模型复测冻结项

- YOLO26n-pose：image size 640、confidence 0.35、ByteTrack。
- HumanArt + RTMPose：YOLOX detector confidence 0.05、detector 640×640、pose 192×256、COCO-17。
- 抽帧：5 fps；不得按各 clip 结果临时改阈值。
- 分组报告：光照、距离、遮挡、scenario、人物框覆盖、`>=0.3/0.5` 关键点可见率、track 碎片、P95、RTF。
- 空场/家具/宠物 clip 报人物框误报；正常躺床/弯腰报跌倒特征误触发，不能只报跌倒 clip 召回。

## 8. M2c 验收门

只有同时满足以下条件才可从 Planned/In progress 进入 Review：

- 至少 8 个必做 C6c clip 可追溯，白天和夜视均有空场与人物样本。
- 至少一段原始容器证明音轨存在/不存在，并记录音视频时间基；“设备带麦克风”不等于服务端媒体有音轨。
- 两个姿态 variant 按冻结参数完成目标设备分组报告。
- 至少一份真实 CS-EP-SDNL1 API/SDK/导出样例完成字段结构报告；若平台不开放，保存权限/能力证据并明确 Blocked。
- 所有报告不含 token、验证码、序列号、姓名和原始健康值。
