# V1 信息采集与多模态模型探索

状态：Active v1.0

更新时间：2026-08-02

v0.9 按 REV-030 外部指标可行性评审修正第 3 节七维映射、3.1 Backlog、命名规范与验证口径。v1.0 按 REV-031 将设备边界升级为 2 × CS-C6c-V101-1J4WF + 1 × CS-EP-SDNL1 双视角基线，冻结云台锁定、帧时间戳、无主动测试约束与验证降级口径。

当前目标：并行确认两台萤石设备能够提供的数据、V1 基线模型可以稳定派生的特征，以及哪些《监测方案》指标暂时不能实现。

## 1. 指标来源与使用原则

《监测方案》是指标目录的主要来源，包含：

1. 步态时空参数与变异性。
2. 昼夜节律。
3. 语音声学与语义特征。
4. 面部表情动态。
5. 社交交互时序。
6. 生理指标。
7. 肌力与姿势稳定性。

这些指标服务于跌倒、认知症、抑郁和诈骗四个风险方向，但“方案希望得到的指标”不等于“现有设备可以直接测量的指标”。

V1 将信息分成四层：

| 层 | 含义 | 示例 |
|---|---|---|
| L0 设备事实 | 设备或接口直接返回，不经模型解释 | 分辨率、在线状态、设备报告字段 |
| L1 标准观测 | 对原始媒体和设备字段做时间、单位和质量标准化 | 视频片段、语音段、睡眠记录 |
| L2 模型特征 | 模型从观测中估计出的结果 | 人体框、关键点、转写文本、声学特征 |
| L3 研究指标 | 对连续特征聚合得到的指标 | 步态变异性、M10/L5、关键词日频次 |

风险等级属于 L4。V1 当前不生成 L4 正式结论。

## 2. 当前设备能力边界

### 2.1 CS-C6c-V101-1J4WF 摄像头（×2，双视角基线）

已知：

- 用户确认设备带麦克风。
- 萤石开放平台通用 SDK 提供设备列表、预览、回放、录像、抓图和告警等能力，但具体设备是否支持，必须查询设备能力集。
- REV-031 起默认基线为两台同型号相机：主相机近似侧视主要行走方向，辅相机前后错开形成约 30°～60° 斜前/斜后视，两路保持 2.5～4 米共同有效区域，分别完成四点以上地面标定；两路独立测量、事件级时间对齐、质量择优后融合，不做同步双目三维重建。
- 该型号按"400 万/2K+ 档"对待：同系列公开参数为最高 2560×1440、4 mm 镜头、H.265、双码流、红外夜视约 10 米、水平云台约 340°、网传帧率自适应；精确型号字符串未在官方页面完整列出，不按 4K 宣传，不预设恒定 25 fps，不承诺任意方向均可精确测量，不假定 RTSP/ONVIF（同系列接口协议为萤石云私有协议）。

待真实验证：

- 精确分辨率、帧率、码流、编码、夜视和音频编码。
- 能否取得原始或解码后连续视频帧；能否取得主码流而非低清预览流。
- 服务端取流还是只能在客户端 SDK 播放；是否必须经过云端。
- 是否保留可靠帧时间戳；长期连续取流的并发、流量、费用和稳定性。
- 直播、回放、抓图、告警短片各自的权限、时延和有效期；SDK 授权及数据用于科研分析的许可范围。
- 视频流是否包含音频，以及音视频时间戳能否稳定对齐。
- 设备侧是否提供人形、声音或其他 AI 事件。

不能仅根据同系列产品手册推断该具体 SKU 的能力。如果实机只能获得 APP 画面或低帧率抓图，该型号不支持精细步态时序测量，只支持人体活动、通行次数和粗略速度。

### 2.2 CS-EP-SDNL1 睡眠仪

萤石官方商品参数列出：

- 59～64 GHz FMCW。
- 50 ms 数据周期。
- 0.5～1.5 m 测距范围。
- 两组测量范围：40～120 bpm 与 6～40 bpm，分辨率均为 1 bpm。
- 通过萤石云视频 APP 联网；官方用户指南支持在/离床、睡眠报告、心率异常、体动异常等功能。

商品参数说明硬件具备生命体征感知能力，但不能证明开放平台会向开发者暴露原始雷达或全部指标。官方用户指南明确 APP 中心率和呼吸率按**分钟周期**上报，不能据此声称可取得 50 ms 级原始生命体征数据。该型号不能测血氧、血压、心电，不能诊断睡眠呼吸暂停，睡眠报告不能等同于 PSG 睡眠分期，也不作为步态测距雷达使用。

安装约束（写入采集规程）：床头固定，距床垫垂直约 0.5～0.7 米，水平靠近身体中部或心脏侧，相对头部中心水平偏移不超过约 0.3 米；设备本体不能晃动，避开电风扇等周期性运动物体；仅支持单人检测，双人床优先采集较近目标并可能互相干扰。

以下项目都必须通过真实 API 响应确认：

- 心率和呼吸率。
- 在床/离床事件。
- 总睡眠时长、入睡/起床、夜间觉醒。
- 睡眠阶段、睡眠效率。
- HRV、AHI、血氧。
- 实时数据、分钟级数据还是日级摘要。

目前公开文档只明确 APP 展示，未找到该型号心率、呼吸率和睡眠报告的公开数据 API；设备采购或合作协议中必须要求萤石书面确认服务器接口、数据字段、时间粒度、历史数据导出、授权方式和费用，否则数据只能由 APP 查看，无法进入融合平台。在字段确认前，不建立睡眠算法，也不把任何字段写进必做验收。

## 3. 七维指标可行性映射

状态定义：

- A：设备直接数据，仍需 API 验证。
- B：可以由模型估计，必须做场景测试。
- C：需要标定、长期采集或额外条件。
- D：当前两台设备无法支持。

| 维度 | 《监测方案》重点指标 | V1 可获得信息 | 状态与边界 |
|---|---|---|---|
| 步态时空与变异性 | 步速、步频、步长/步幅/步宽、支撑/摆动时间、对称性、CV% | 2D 姿态点、足部可见性、像素/归一化位移、步周期、左右时序 | B/C；不安排任何主动步行测试，步态指标全部来自自然行走片段的自动发现与质量筛选；真实尺度需锁定云台和工作人员地面标定的自然通道；不预设恒定 25 fps（网传帧率自适应），必须保存真实帧时间戳并检测丢帧/抖动/降帧/码流切换，双支撑等短时间相受约 40 ms 帧间隔、运动模糊和关键点误差叠加限制；双侧视角独立测量+事件级时间对齐+质量择优融合，不做同步双目三维重建；步态疾病类型只能输出"异常步态概率"式筛查；谐波比 HR/iHR 是躯干 IMU 频谱指标，视频不得沿用其定义和文献阈值 |
| 昼夜节律 | 睡眠时长、IV、IS、RA、M10/L5、活动度 | 睡眠设备报告字段、摄像头视野内活动/静止窗口 | A/C/D；在床时段趋势字段视真实接口而定；IV、IS、RA、M10、L5 是非参数 24 小时节律指标，需要 6～7 天接近全天候连续活动计数，单一床旁设备加单房间摄像头覆盖不了白天外出活动，当前不可得；不得用余弦拟合冒充，Cosinor 只产生 mesor、振幅和峰相位 |
| 语音声学/语义 | 语速、停顿、F0、响度、谱特征、词汇、关键词、情感极性 | VAD 段、转写与时间戳、关键词类别、声学特征、信噪比 | B；以每周固定 60～120 秒问答/图片描述等标准化任务为主要采集形态；Jitter、Shimmer、HNR、共振峰仅限近讲标准化录音，不从远场自然对话直接提取并套用临床阈值；输出前必须确认说话人为老人本人且 SNR 合格，否则不输出 |
| 面部表情动态 | AU、微笑、表情多样性、转换速度 | 人脸可见率、脸部关键点、头姿、blendshape 或候选 AU | C/D；高位远场机位脸部像素不足，常规监控形态不支持可靠 AU；仅保留设备交互时的主动近景采样；微表情、秒级恐惧/兴奋、眼神躲闪不支持，不作强证据 |
| 社交交互时序 | 外出、访客、通话、联系人多样性、房间停留 | 视野内匿名人数、共现时长、语音活动时长、当前区域停留、离开/回到视野窗口 | B/D；无门口机、门锁和电话元数据，外出只能以"离开视野"弱代理表达；访客身份、外出目的地、活动半径、通话对象与频次、联系人多样性不可得 |
| 生理指标 | 心率、呼吸率、HRV、血氧、AHI、体温、血压 | 睡眠仪开放接口实际返回的生命体征或摘要 | A/D；只接受接口实际返回字段；聚合 bpm 不能反推 SDNN/RMSSD/pNN50/LF/HF；血氧、AHI、体温、血压无当前设备证据；视频 rPPG 不列为常规能力，仅限静坐近景、质量门控下的实验性探索 |
| 功能活动表现（原"肌力与姿势稳定"） | 坐站时间、起立速度、转身时间、躯干摇摆 | 起坐/转身时长、躯干与髋部位移、图像坐标摆动代理、动作完成质量 | B/C；"肌力"改称"坐站和功能活动表现"，测的是功能表现而非力量；不安排口令化主动测试，单腿站立、睁/闭眼站立类受控项目不采集；单目视频不能测 COP 面积/速度，视频代理量命名为"视觉躯干/重心投影摇摆代理" |

### 3.1 V1 指标字段优先级

以下列表将《监测方案》的具体指标转换为采集 Backlog。

| 优先级 | 指标组 | V1 字段或产物 | 说明 |
|---|---|---|---|
| P0 | 视频质量 | fps、resolution、codec、frame_gap、brightness、blur、person_visible | 决定后续模型结论是否可信 |
| P0 | 人体与姿态 | bbox、track_id、关键点坐标/置信度、pose_coverage | 所有动作与步态代理量的基础 |
| P0 | 跌倒相关 | 髋部垂直位移、躯干角、人体框宽高比、横卧时长、静止时长 | 先做可观察事件，不先训练跌倒分类器 |
| P0 | 基础动作 | 行走、坐下、起立、弯腰、转身、躺床的时间窗口 | 用于负样本与误报分析 |
| P0 | 音频质量/VAD | sample_rate、SNR 代理、静音比例、speech_segments | 先判断摄像头麦克风是否可用 |
| P0 | 中文语音 | transcript、字符时间戳、CER、关键词类别与命中时间 | 原始音频只在受控本地处理 |
| P0 | 睡眠接口 | 原始字段、单位、时间粒度、缺失、延迟、在离床表达 | 不在字段确认前重命名为医学指标 |
| P1 | 步态窗口 | 步频、步周期、左右时序比、归一化步长代理、窗口内 CV% | 全部来自自然行走自动发现；需要足部可见、连续稳定步态周期和工作人员完成地面标定的自然通道；真实步长/步速在标定后才报告；每个片段输出质量分数，低质量只输出"经过/活动" |
| P1 | 功能活动表现 | 起立用时、转身用时、躯干/髋部摆动代理 | 起立/转身计时来自自然活动观察，不设口令任务；不使用 COP 名称描述视频代理量 |
| P1 | 声学特征 | 语速、停顿、F0 及变异、响度、MFCC | 记录环境噪声和有效语音时长；Jitter、Shimmer、HNR、共振峰仅在近讲固定朗读任务下计算，不从远场对话提取 |
| P1 | 语义统计 | TTR、重复/修正频次、负性词比例、诈骗关键词与语义意图 | 仅在有足够有效转写时计算；诈骗侧采用关键词+语义意图+异常行为三证据融合，任何单一关键词不得直接触发告警 |
| P1 | 面部可用性 | face_pixel_size、face_coverage、head_pose、blink 代理 | 先判断机位是否支持；高位远场机位默认不满足 AU 条件，不跑表情模型 |
| P1 | 睡眠/节律 | TST、入睡/起床、WASO、觉醒、效率、活动窗口 | 只映射设备真实返回字段 |
| 暂不可得 | 24 小时节律 | IV、IS、RA、M10、L5 | 需要 6～7 天接近 24 小时连续活动计数；床旁设备+单房间摄像头无法覆盖白天外出活动，且不能用余弦拟合冒充非参数指标 |
| 暂不可得 | 生理扩展 | SDNN、RMSSD、pNN50、HF、LF/HF、血氧、AHI、体温、血压 | 除非睡眠仪 API 明确提供足够原始量 |
| 暂不可得 | 门锁/电话行为 | 出门记录、访客身份、外出目的地、通话对象/频次/号码、联系人多样性、活动半径 | 当前没有对应设备或数据授权 |
| 暂不可得 | 视频测量冒充项 | COP 面积/速度、IMU 谐波比 HR/iHR、微表情与眼神躲闪类情绪判定 | 分别依赖力台、躯干加速度计和近景高帧率正脸；视频只能另立代理量并单独验证 |

| 不采集 | 主动测试类 | TUG、规定路线步行、5 次坐站口令、单腿/闭眼站立、主动睡眠测试 | 家庭验证不安排任何主动步行或睡眠测试（REV-031）；相机标定、对时和安装验收全部由工作人员完成 |

### 3.1.1 指标命名规范（REV-030 冻结）

- "肌力"统一改称"坐站和功能活动表现"。
- "COP 面积/速度"改称"视觉躯干/重心投影摇摆代理量"。
- "情绪识别"改称"面部/语音情绪线索"。
- "抑郁/认知诊断"改称"需进一步量表或临床评估的风险提示"。
- "诈骗识别"改称"疑似高风险交互事件"。
- "单支撑线/双支撑线"改称"单支撑时间/双支撑时间"；"步线长度"改称"步长/步幅"。

### 3.2 结构化基线信息

《监测方案》还要求人口学和临床基线，包括身高、体重、性别、既往史、服药史、受教育程度，以及 MMSE/MoCA、PHQ-9/GDS-15、TUG、IADL 等量表或测试。

V1 的处理方式：

- 只定义人工录入/导入接口，不对量表进行自动推断。
- 身高可用于“标准化步长”探索，但只有完成相机标定后才能报告真实尺度。
- Demo 默认使用明确标记的虚构档案，不使用真实老人身份或健康信息。
- 真实量表数据只用于后续验证对照，不能作为模型从视频或语音自动生成的标签。

### 对四类风险的 V1 处理

- 跌倒：P0。探索姿态、下降、横卧、静止、起坐和转身特征；事件结论必须报告灵敏度、漏报率和每户每天误报次数，不接受只报"准确率"。
- 认知症：只验证语音、活动、睡眠和步态指标是否可采，不输出风险诊断；任何筛查结论命名为"需进一步量表或临床评估的风险提示"。
- 抑郁：只验证长期趋势所需字段，不从单次表情或语音推断抑郁。
- 诈骗：改称"疑似高风险交互事件"；仅使用主动开启或脚本化对话，采用关键词+语义意图+异常行为三证据融合，任何单一关键词不得直接触发告警；不做全天候窃听。

## 4. V1 采集流水线

```mermaid
flowchart LR
    P["Capability Probe<br/>设备与接口能力探测"]
    C["Recorder / Importer<br/>录制或导入"]
    N["Normalizer<br/>时间、格式、质量"]
    X["Extractor Plugins<br/>视频、音频、睡眠"]
    A["Aggregator<br/>窗口与统计"]
    Q["Feasibility Report<br/>覆盖率、速度、失败案例"]

    P --> C --> N --> X --> A --> Q
```

### 4.1 Capability Probe

每次探测必须保存：

- 接口名称与文档版本。
- 请求时间、状态码和脱敏后的响应结构。
- 账号权限、调用频率和能力集。
- 是否需要客户端 SDK、服务端 API 或人工导出。
- 失败原因与下一步联系人。

AppKey、AccessToken、设备验证码和设备序列号不得提交到仓库。

### 4.2 Recorder / Importer

输入优先级：

1. 实际 C6c 录制的视频和音频。
2. 实际睡眠仪 API 或人工导出。
3. 同接口格式的脱敏 Fixture。
4. 公开数据仅用于模型基线，不代替真实设备验证。

设备无关的网络入口已实现为 `capture-stream`：端点仅从进程环境读取，经 open/read timeout、媒体时长、wall time 和 packet 上限约束，从首个视频关键帧开始 codec-copy 到 owner-only Matroska，再执行同一容器 timing gate。HTTP loopback E1 已进一步在 L40 上完成真实姿态与语言 Pipeline；这只关闭“网络输入到同容器回放”的 adapter seam，不证明 C6c RTSP、萤石平台权限、音轨、重连或真实 drift。原始采集物会被持久化，必须先落实同意、受控存储、留存和删除责任。

在单次采集之上，`qualify-stream` 以多个独立连接检查每次 readiness 以及视频尺寸/帧率、音频采样率/声道等格式稳定性；连接失败被归一化为固定错误码，不把 endpoint 或底层 message 写入报告。它不跨连接拼接媒体，也不把计划性 reopen 解释成断线恢复或长稳。

通过资格门后，`run-stream-session` 将多个独立有界 capture 组织为 segment/gap/interruption ledger：非 ready 后由外部 supervisor 等待 backoff 并新开一个 raw，不修改或拼接前一段。`exercise-stream-recovery` 在同一 loopback HTTP endpoint 上执行 ready→503→ready，并要求实际注入遥测和恢复事件同时成立；这只证明 supervisor 状态机。真实 segmented-session 长稳必须让 wall time 与累计 ready media 的声明值和实际值分别达到至少 30 分钟，空闲 gap/backoff 不能冒充有效媒体；该结论仍与同连接连续性、非自愿断流、RTSP/packet loss 容忍和设备平台证据分开。

### 4.3 Normalizer

输出至少包含：

- asset_id、modality、source_type、evidence_level，并在 Observation 中保存脱敏的 device_ref/elder_ref。
- UTC 时间与媒体内部相对时间。
- 视频分辨率、FPS、编码、帧数和时间戳间断。
- 音频采样率、声道、编码、响度和静音比例。
- 睡眠字段原名、标准字段、单位、原始时间粒度和缺失原因。

### 4.4 Extractor Plugin

所有提取器统一记录：

- extractor_name 与 extractor_version。
- model_name、权重摘要和许可证。
- 输入时间范围、输出时间范围和推理耗时。
- confidence、quality、missing_reason。
- CPU/GPU、显存、软件环境。

模型依据：

- [MediaPipe Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/python) 支持图像、视频和直播模式，输出 33 个姿态点及可见性。
- [Ultralytics Pose](https://docs.ultralytics.com/tasks/pose) 当前默认人体姿态模型输出 17 个 COCO 关键点；[Track 模式](https://docs.ultralytics.com/modes/track) 可用于视频轨迹。
- [MMPose](https://github.com/open-mmlab/mmpose) 提供多种姿态模型和 Apache 2.0 框架许可。
- [MMAction2](https://github.com/open-mmlab/mmaction2) 提供 PoseC3D、ST-GCN 等骨架动作识别实现。
- [MediaPipe Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker) 输出 478 个脸部点与 52 个 blendshape。
- [OpenFace AU 文档](https://github.com/TadasBaltrusaitis/OpenFace/wiki/Action-Units) 支持 AU01、AU02、AU04、AU06、AU12 等部分 FACS AU，但许可证和实际机位精度需要单独 Review。
- [FunASR](https://github.com/modelscope/FunASR) 提供 Paraformer-zh、FSMN-VAD、标点和时间戳能力。
- [OpenAI Whisper](https://github.com/openai/whisper) 提供多语种 ASR 与不同规模模型。
- [openSMILE](https://audeering.github.io/opensmile/) 提供语音声学特征提取。
- [YAMNet](https://www.tensorflow.org/tutorials/audio/transfer_learning_audio) 是 521 类通用声音分类基线。

## 6. 首轮实验集

### 6.1 视频

使用实际 C6c 录制短片，至少覆盖：

- 白天与夜视。
- 近距离与远距离。
- 正面、侧面和部分遮挡。
- 行走、坐下、起立、弯腰捡物、躺床、转身。
- 由健康成年人在安全垫和保护人员条件下完成的受控跌倒/近跌倒。

不要求老人参与危险跌倒动作。

每段记录机位高度、俯仰角、人与相机距离、照明、分辨率和动作真值。

### 6.2 音频

使用明确同意的普通话短对话，覆盖：

- 安静、电视背景声、远场和多人重叠。
- 普通对话、停顿较多对话。
- 中性句与脚本化诈骗关键词句。

只评估 VAD、转写、关键词和客观声学特征；不把测试者情绪标签当作健康诊断真值。

### 6.3 睡眠

优先采集连续三晚的设备输出，用于评估：

- 字段完整率、时间覆盖率、重复和断点。
- 日级报告生成时间。
- 多晚字段一致性。
- 设备离线与无人状态表达。

V1 不在没有参考设备的情况下声称心率、呼吸或睡眠分期准确率。

## 7. 选型指标

### 视频模型

- 人体/姿态有效帧覆盖率。
- 关键点平均可见率与轨迹中断次数。
- 日常动作误触发情况。
- 实际设备视频上的 FPS、P95 帧耗时、显存。
- 白天/夜视、距离、遮挡分组结果。

### 音频模型

- VAD 段边界和漏检。
- 中文字错误率 CER。
- 目标关键词召回与误报。
- 实时系数、显存和长音频稳定性。
- 电视声、多人声和远场分组结果。

### 睡眠采集

- API 成功率、记录完整率、数据延迟。
- 字段单位和时间粒度一致性。
- 缺失、离床、设备离线能否区分。

模型晋级不能只看一段效果视频，必须保留固定样本、配置和失败案例。

### 三层验证口径（REV-030 起作为 V2 验收框架）

- 测量层：与人工计时、RGB-D、ECG、呼吸带等参考同步；报告 MAE、Bland–Altman 一致性、ICC 和有效数据率。
- 事件层：受控模拟跌倒、失稳、夜间异常活动、疑似诈骗交互；报告事件召回率、精确率、每户每天误报数和响应延迟。
- 风险层：只报告与 TUG、MoCA、PHQ-9/GDS 等基线量表的相关性和趋势一致性；AUC 必须附 95% 置信区间，不在小样本上宣称临床预测性能。

内部工程验收暂定：步速 MAE ≤ 0.05 m/s、夜间心率 MAE ≤ 3 bpm、呼吸率 MAE ≤ 2 bpm、床边离床召回 ≥ 95%、语音结果只在合格 SNR 和明确说话人条件下输出。这些是项目验收门槛，不是医疗器械标准。

双视角质量指标（REV-031）：两路步速差、两路步频差、左右脚关键点一致性、跨视角行走事件匹配率、单侧遮挡率、双侧共同有效步数、相机位置漂移量、两路时间戳偏差、双路一致的跌倒置信度。这些指标用于区分"老人真的变慢了"与"某一路相机当天受到遮挡、逆光或网络降帧影响"。

验证定位（REV-031 冻结）：研究期间不增加任何独立参照硬件，因此不能声称完成与动作捕捉、压力步道或 PSG 的金标准精度验证。可完成的是：视频片段人工复核、已标定自然通道的通过时间复核、同一家庭日内/日间/周间重复性、数据覆盖率/漏检率/误检率、不同光照/衣着/遮挡/助行器条件下的稳定性、相对个人基线的趋势检测能力、睡眠仪原生输出的完整率和连续性。研究名称使用"无感监测可行性与纵向稳定性验证"，不写"临床测量准确性验证"；绝对精度引用既有单 RGB 研究作为外部依据。前瞻性跌倒"需要关注"分层的内部验证目标设为 AUC 0.75～0.82，不承诺 0.90 以上。

## 8. 隐私与数据管理

沿用《监测方案》的隐私优先原则：

- 原始视频和音频只在受控本地环境保存和处理。
- 对外产物只包含脱敏的特征、时间窗口和质量信息。
- 语音采集必须主动开启并有明确授权，不进行全天候监听。
- 人脸只用于几何/表达变化探索，不做人脸身份库。
- 用户 ID 与设备序列号分离保存。
- G4 派生事件不复制原始人体框、关键点、阶段标签或源文件路径，只保留归一化代理、质量门和摘要引用。

《监测方案》提出项目结束后 30 日删除原始媒体，以及在特征传输前使用 ε=1.0 的差分隐私。前者作为暂定留存上限；后者必须先定义邻接数据集、敏感度、具体机制和按人/按日的隐私预算及组合消耗，不能仅写一个 ε 值就视为已实现。

涉及视频、语音、面部、健康和行踪类敏感个人信息，正式采集前必须取得单独同意并完成个人信息保护影响评估，并为访客与通话另一方设计告知/最小化机制；人脸相关处理遵循 2025-06-01 起施行的《人脸识别技术应用安全管理办法》的充分必要、影响最小和最短保存要求。语音链路统一为端侧完成 VAD、说话人确认、ASR 和意图判定，对外只上传事件类型、置信度、时间和质量分，不上传转写文本或原始音频。
