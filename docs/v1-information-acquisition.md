# V1 信息采集与多模态模型探索

状态：Active v0.2

更新时间：2026-07-22

当前目标：并行确认两台萤石设备能够提供的数据、V1 基线模型可以稳定派生的特征，以及哪些《监测方案》指标暂时不能实现。

## 1. 指标来源与使用原则

《监测方案》是指标目录的主要来源，包含：

1. 步态时空参数与变异性。
2. 昼夜节律。
3. 语音声学与语义特征。
4. 面部表情动态。
5. 社交交互时序。
6. 生理指标。
7. 肌力与姿势稳定性。

这些指标服务于跌倒、认知症、抑郁和诈骗四个风险方向，但“方案希望得到的指标”不等于“现有设备可以直接测量的指标”。

V1 将信息分成四层：

| 层 | 含义 | 示例 |
|---|---|---|
| L0 设备事实 | 设备或接口直接返回，不经模型解释 | 分辨率、在线状态、设备报告字段 |
| L1 标准观测 | 对原始媒体和设备字段做时间、单位和质量标准化 | 视频片段、语音段、睡眠记录 |
| L2 模型特征 | 模型从观测中估计出的结果 | 人体框、关键点、转写文本、声学特征 |
| L3 研究指标 | 对连续特征聚合得到的指标 | 步态变异性、M10/L5、关键词日频次 |

风险等级属于 L4。V1 当前不生成 L4 正式结论。

## 2. 当前设备能力边界

### 2.1 CS-C6c-V101-1J4WF 摄像头

已知：

- 用户确认设备带麦克风。
- 萤石开放平台通用 SDK 提供设备列表、预览、回放、录像、抓图和告警等能力，但具体设备是否支持，必须查询设备能力集。

待真实验证：

- 精确分辨率、帧率、码流、编码、夜视和音频编码。
- 服务端取流还是只能在客户端 SDK 播放。
- 直播、回放、抓图、告警短片各自的权限、时延和有效期。
- 视频流是否包含音频，以及音视频时间戳能否稳定对齐。
- 设备侧是否提供人形、声音或其他 AI 事件。

不能仅根据同系列产品手册推断该具体 SKU 的能力。

### 2.2 CS-EP-SDNL1 睡眠仪

萤石官方商品参数列出：

- 59～64 GHz FMCW。
- 50 ms 数据周期。
- 0.5～1.5 m 测距范围。
- 两组测量范围：40～120 bpm 与 6～40 bpm。
- 通过萤石云视频 APP 联网。

商品参数说明硬件具备生命体征感知能力，但不能证明开放平台会向开发者暴露原始雷达或全部指标。以下项目都必须通过真实 API 响应确认：

- 心率和呼吸率。
- 在床/离床事件。
- 总睡眠时长、入睡/起床、夜间觉醒。
- 睡眠阶段、睡眠效率。
- HRV、AHI、血氧。
- 实时数据、分钟级数据还是日级摘要。

在字段确认前，不建立睡眠算法，也不把任何字段写进必做验收。

## 3. 七维指标可行性映射

状态定义：

- A：设备直接数据，仍需 API 验证。
- B：可以由模型估计，必须做场景测试。
- C：需要标定、长期采集或额外条件。
- D：当前两台设备无法支持。

| 维度 | 《监测方案》重点指标 | V1 可获得信息 | 状态与边界 |
|---|---|---|---|
| 步态时空与变异性 | 步速、步长、步频、支撑/摆动相、对称性、CV% | 2D/近似 3D 姿态点、足部可见性、像素/归一化位移、步周期、左右时序 | B/C；真实 cm/s 和真实步长需要相机标定、地面尺度和稳定机位 |
| 昼夜节律 | 睡眠时长、IV、IS、RA、M10/L5、活动度 | 睡眠设备报告字段、摄像头视野内活动/静止窗口 | A/C；IV、IS、RA、M10/L5 需要连续多日数据，V1 只验证计算链和数据完整性 |
| 语音声学/语义 | 语速、停顿、F0、HNR、Jitter、Shimmer、词汇、关键词、情感极性 | VAD 段、转写与时间戳、关键词类别、声学特征、信噪比 | B；远场、电视声和多人语音是主要误差源；只在明确开启和同意下采集 |
| 面部表情动态 | AU06/AU12/AU04、微笑、表情多样性、转换速度 | 人脸可见率、脸部关键点、头姿、blendshape 或候选 AU | B/C；CCTV 远距离可能没有足够脸部像素；blendshape 不等同于 FACS AU |
| 社交交互时序 | 外出、访客、通话、联系人多样性、房间停留 | 摄像头视野内匿名人数、共现时长、语音活动时长、当前区域停留 | B/D；没有门锁和电话元数据，不能可靠声称外出频率、联系人多样性或通话对象 |
| 生理指标 | 心率、HRV、血氧、呼吸率、AHI | 睡眠仪开放接口实际返回的生命体征或摘要 | A/D；若只有聚合 bpm，不能反推出 HRV；血氧和 AHI 不得默认存在 |
| 肌力与姿势稳定 | 起立速度、转身时间、身体摆动、单腿站立、COP | 起坐/转身时长、躯干与髋部位移、图像坐标摆动代理、动作完成质量 | B/C；单目视频不能直接测力平台意义上的 COP 面积/速度 |

### 3.1 V1 指标字段优先级

以下列表将《监测方案》的具体指标转换为采集 Backlog。

| 优先级 | 指标组 | V1 字段或产物 | 说明 |
|---|---|---|---|
| P0 | 视频质量 | fps、resolution、codec、frame_gap、brightness、blur、person_visible | 决定后续模型结论是否可信 |
| P0 | 人体与姿态 | bbox、track_id、关键点坐标/置信度、pose_coverage | 所有动作与步态代理量的基础 |
| P0 | 跌倒相关 | 髋部垂直位移、躯干角、人体框宽高比、横卧时长、静止时长 | 先做可观察事件，不先训练跌倒分类器 |
| P0 | 基础动作 | 行走、坐下、起立、弯腰、转身、躺床的时间窗口 | 用于负样本与误报分析 |
| P0 | 音频质量/VAD | sample_rate、SNR 代理、静音比例、speech_segments | 先判断摄像头麦克风是否可用 |
| P0 | 中文语音 | transcript、字符时间戳、CER、关键词类别与命中时间 | 原始音频只在受控本地处理 |
| P0 | 睡眠接口 | 原始字段、单位、时间粒度、缺失、延迟、在离床表达 | 不在字段确认前重命名为医学指标 |
| P1 | 步态窗口 | 步频、步周期、左右时序比、归一化步长代理、窗口内 CV% | 需要足部可见和连续稳定轨迹 |
| P1 | 姿势稳定 | 起立用时、转身用时、躯干/髋部摆动代理、单腿站立可见时长 | 不使用 COP 名称描述视频代理量 |
| P1 | 声学特征 | 语速、停顿、F0 及变异、HNR、Jitter、Shimmer、MFCC | 记录环境噪声和有效语音时长 |
| P1 | 语义统计 | TTR、重复/修正频次、负性词比例、五类诈骗关键词 | 仅在有足够有效转写时计算 |
| P1 | 面部可用性 | face_pixel_size、face_coverage、head_pose、blink 代理 | 先判断机位是否支持，再决定是否跑表情模型 |
| P1 | 睡眠/节律 | TST、入睡/起床、WASO、觉醒、效率、活动窗口 | 只映射设备真实返回字段 |
| P2 | 多日节律 | IV、IS、RA、M10、L5、M10 中点 | 需要连续多日且缺失率合格 |
| 暂不可得 | 生理扩展 | SDNN、RMSSD、pNN50、HF、LF/HF、血氧、AHI、体温、血压 | 除非睡眠仪 API 明确提供足够原始量 |
| 暂不可得 | 门锁/电话行为 | 出门记录、访客身份、通话对象、联系人多样性、活动半径 | 当前没有对应设备或数据授权 |

### 3.2 结构化基线信息

《监测方案》还要求人口学和临床基线，包括身高、体重、性别、既往史、服药史、受教育程度，以及 MMSE/MoCA、PHQ-9/GDS-15、TUG、IADL 等量表或测试。

V1 的处理方式：

- 只定义人工录入/导入接口，不对量表进行自动推断。
- 身高可用于“标准化步长”探索，但只有完成相机标定后才能报告真实尺度。
- Demo 默认使用明确标记的虚构档案，不使用真实老人身份或健康信息。
- 真实量表数据只用于后续验证对照，不能作为模型从视频或语音自动生成的标签。

### 对四类风险的 V1 处理

- 跌倒：P0。探索姿态、下降、横卧、静止、起坐和转身特征。
- 认知症：只验证语音、活动、睡眠和步态指标是否可采，不输出风险诊断。
- 抑郁：只验证长期趋势所需字段，不从单次表情或语音推断抑郁。
- 诈骗：仅使用主动开启或脚本化对话，探索关键词、紧迫语义与同步行为；不做全天候窃听。

## 4. V1 采集流水线

```mermaid
flowchart LR
    P["Capability Probe<br/>设备与接口能力探测"]
    C["Recorder / Importer<br/>录制或导入"]
    N["Normalizer<br/>时间、格式、质量"]
    X["Extractor Plugins<br/>视频、音频、睡眠"]
    A["Aggregator<br/>窗口与统计"]
    Q["Feasibility Report<br/>覆盖率、速度、失败案例"]

    P --> C --> N --> X --> A --> Q
```

### 4.1 Capability Probe

每次探测必须保存：

- 接口名称与文档版本。
- 请求时间、状态码和脱敏后的响应结构。
- 账号权限、调用频率和能力集。
- 是否需要客户端 SDK、服务端 API 或人工导出。
- 失败原因与下一步联系人。

AppKey、AccessToken、设备验证码和设备序列号不得提交到仓库。

### 4.2 Recorder / Importer

输入优先级：

1. 实际 C6c 录制的视频和音频。
2. 实际睡眠仪 API 或人工导出。
3. 同接口格式的脱敏 Fixture。
4. 公开数据仅用于模型基线，不代替真实设备验证。

### 4.3 Normalizer

输出至少包含：

- asset_id、modality、source_type、evidence_level，并在 Observation 中保存脱敏的 device_ref/elder_ref。
- UTC 时间与媒体内部相对时间。
- 视频分辨率、FPS、编码、帧数和时间戳间断。
- 音频采样率、声道、编码、响度和静音比例。
- 睡眠字段原名、标准字段、单位、原始时间粒度和缺失原因。

### 4.4 Extractor Plugin

所有提取器统一记录：

- extractor_name 与 extractor_version。
- model_name、权重摘要和许可证。
- 输入时间范围、输出时间范围和推理耗时。
- confidence、quality、missing_reason。
- CPU/GPU、显存、软件环境。

## 5. 候选模型矩阵

这里区分“V1 已采用基线”和“待对比候选”。基线只用于打通链路，不代表已经晋级 V2。

| 模态/任务 | 候选 | 可得到的输出 | V1 决策 |
|---|---|---|---|
| 单人姿态快速候选 | MediaPipe Pose Landmarker | 每人 33 个图像/世界姿态点、可见性、可选分割 | 待对比；需要 CPU/移动端基线时加入 |
| 多人/远距离姿态 | YOLO26n-pose + ByteTrack | 人体框、17 个 COCO 关键点、置信度、轨迹 | V1 已采用基线；V2 前必须解决 AGPL/Enterprise 许可证门或替换 |
| 姿态精度候选 | MMPose / RTMPose 系列 | 可配置人体检测和关键点模型 | 当前两条基线不足时再测；框架为 Apache 2.0 |
| 跌倒时序 | 规则特征 | 髋部下降、躯干角度、宽高比、横卧与静止窗口 | V1 首选，可解释且不需要训练集 |
| 时序动作模型 | MMAction2 PoseC3D / ST-GCN 系列 | 骨架序列动作分类 | V2 候选；只有获得足够标注片段后才启动 |
| 人脸几何 | MediaPipe Face Landmarker | 478 个 3D 人脸点、52 个 blendshape、变换矩阵 | 只做可见性和表达变化探索，不直接当 FACS AU |
| FACS AU | OpenFace | AU presence/intensity、头姿、眼动等 | 仅做对照实验；研究代码、老化工程栈和商业许可需审查 |
| 中文 VAD/ASR | FunASR FSMN-VAD + Paraformer-zh + CT-Punc | 语音段、中文转写、时间戳、标点 | V1 已采用中文基线；固定权重按 SHA-256 追溯 |
| 多语种 ASR 对照 | OpenAI Whisper small/turbo | 多语种转写、语言和时间段信息 | 对照；单独使用 Python 3.11 环境测试 |
| 声学特征 | openSMILE eGeMAPS | F0、HNR、Jitter、Shimmer、能量、谱特征等 | 只输出客观声学量，不直接输出疾病判断 |
| 环境声音 | YAMNet | 521 类通用音频事件及 embedding | 低优先级；先确认跌倒撞击/呼救是否在实际音频中可分 |
| 睡眠信息 | 字段映射与质量规则 | 心率/呼吸/在离床/睡眠摘要等实际开放字段 | 不先上模型；先完成 API 字段与缺失分析 |

模型依据：

- [MediaPipe Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/python) 支持图像、视频和直播模式，输出 33 个姿态点及可见性。
- [Ultralytics Pose](https://docs.ultralytics.com/tasks/pose) 当前默认人体姿态模型输出 17 个 COCO 关键点；[Track 模式](https://docs.ultralytics.com/modes/track) 可用于视频轨迹。
- [MMPose](https://github.com/open-mmlab/mmpose) 提供多种姿态模型和 Apache 2.0 框架许可。
- [MMAction2](https://github.com/open-mmlab/mmaction2) 提供 PoseC3D、ST-GCN 等骨架动作识别实现。
- [MediaPipe Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker) 输出 478 个脸部点与 52 个 blendshape。
- [OpenFace AU 文档](https://github.com/TadasBaltrusaitis/OpenFace/wiki/Action-Units) 支持 AU01、AU02、AU04、AU06、AU12 等部分 FACS AU，但许可证和实际机位精度需要单独 Review。
- [FunASR](https://github.com/modelscope/FunASR) 提供 Paraformer-zh、FSMN-VAD、标点和时间戳能力。
- [OpenAI Whisper](https://github.com/openai/whisper) 提供多语种 ASR 与不同规模模型。
- [openSMILE](https://audeering.github.io/opensmile/) 提供语音声学特征提取。
- [YAMNet](https://www.tensorflow.org/tutorials/audio/transfer_learning_audio) 是 521 类通用声音分类基线。

## 6. 首轮实验集

### 6.1 视频

使用实际 C6c 录制短片，至少覆盖：

- 白天与夜视。
- 近距离与远距离。
- 正面、侧面和部分遮挡。
- 行走、坐下、起立、弯腰捡物、躺床、转身。
- 由健康成年人在安全垫和保护人员条件下完成的受控跌倒/近跌倒。

不要求老人参与危险跌倒动作。

每段记录机位高度、俯仰角、人与相机距离、照明、分辨率和动作真值。

### 6.2 音频

使用明确同意的普通话短对话，覆盖：

- 安静、电视背景声、远场和多人重叠。
- 普通对话、停顿较多对话。
- 中性句与脚本化诈骗关键词句。

只评估 VAD、转写、关键词和客观声学特征；不把测试者情绪标签当作健康诊断真值。

### 6.3 睡眠

优先采集连续三晚的设备输出，用于评估：

- 字段完整率、时间覆盖率、重复和断点。
- 日级报告生成时间。
- 多晚字段一致性。
- 设备离线与无人状态表达。

V1 不在没有参考设备的情况下声称心率、呼吸或睡眠分期准确率。

## 7. 选型指标

### 视频模型

- 人体/姿态有效帧覆盖率。
- 关键点平均可见率与轨迹中断次数。
- 日常动作误触发情况。
- 实际设备视频上的 FPS、P95 帧耗时、显存。
- 白天/夜视、距离、遮挡分组结果。

### 音频模型

- VAD 段边界和漏检。
- 中文字错误率 CER。
- 目标关键词召回与误报。
- 实时系数、显存和长音频稳定性。
- 电视声、多人声和远场分组结果。

### 睡眠采集

- API 成功率、记录完整率、数据延迟。
- 字段单位和时间粒度一致性。
- 缺失、离床、设备离线能否区分。

模型晋级不能只看一段效果视频，必须保留固定样本、配置和失败案例。

## 8. 隐私与数据管理

沿用《监测方案》的隐私优先原则：

- 原始视频和音频只在受控本地环境保存和处理。
- 对外产物只包含脱敏的特征、时间窗口和质量信息。
- 语音采集必须主动开启并有明确授权，不进行全天候监听。
- 人脸只用于几何/表达变化探索，不做人脸身份库。
- 用户 ID 与设备序列号分离保存。

《监测方案》提出项目结束后 30 日删除原始媒体，以及在特征传输前使用 ε=1.0 的差分隐私。前者作为暂定留存上限；后者必须先定义具体机制、敏感度和效用评估，不能仅写一个 ε 值就视为已实现。

## 9. V1-M1 立即行动

1. 获取萤石开发应用、测试账号和两台设备，但密钥不入库。
2. 对摄像头执行设备列表、能力集、直播、回放、抓图、告警和音频探测。
3. 对睡眠仪获取一份真实 API/导出样例及字段说明。
4. 使用 C6c 录制首批白天、夜视、远近距离视频与受控音频。
5. 在冻结的真实样本上运行已打通的 YOLO26 pose/FunASR 基线，并加入 RTMPose、MediaPipe 或 Whisper 对照。

设备无关基线已在 Slurm L40 上通过 E1 smoke，见 [V1-M2a 初测报告](reports/v1-m2a-multimodal-smoke.md)。该结果不改变前四项真实设备任务的证据状态。
